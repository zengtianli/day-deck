## 九问

1. **功能与主要问题**：已有Notihub服务的使用者离开Mac后，查看今天要做什么、按日期阅读通知总结/时间线，并随手记想法；具体路径是读取日期索引与未完成待办、选一天、展开正文、提交随手记或改变待办状态、按服务回执确认。失败保留草稿，缓存显示陈旧度。只有用户主动加入提醒事项才走本机EventKit，不自动推送或打角标。
2. **目标用户**：已有Notihub复盘工作台及服务访问资格的个人使用者，典型为早晨看待办、离开Mac后查信息、晚间复盘；不是开放注册的多租户服务。正式客户端只有固定个人服务与独立审核服务两个受约束入口，没有任意服务器设置。审核账号只访问合成数据。
3. **独立贡献**：同一份数据适配触屏、小屏、iPad/Vision宽屏和配对手表摘要，不在手机再采集一份系统通知或建第二个账本。贡献包括陈旧度、失败保留草稿、待办分组/搜索、本机提醒事项映射、云端回执、云端写入与交给Mac排队的明确区分；本次增加配置/更新及独立审核登录/退出边界。当前性能仍待绑定新输入，不引用旧包资源数作为当前实测。
4. **beta与反馈**：当前源码SwiftPM核心60项通过，覆盖生产解析、回执、隔离地址/草稿、退出请求；不代替原生实测。此前54项真实App内product_basics及四平台launch对应旧输入，新源码native_ui/product_basics和受影响平台验证仍由固定脚本/原队列接续。云端独立实例已通过真实HTTPS读写与会话/个人数据隔离，其原件归notifhub-cloud；客户端本轮尚无真实模拟器审核账号通过回执。没有可证的外部beta人数/反馈统计，不编造案例；真机、苹果跨设备iCloud传输未由本轮证明。
5. **独立产品还是套件**：这是Notihub工作台的移动客户端，属于同一产品家族；Mac菜单栏端为notifhub-bar-mac，数据生产端为notifhub-cli，服务端为notifhub-cloud。移动端读同一服务，一个工程覆盖iPhone/iPad/Vision与配对Watch，不是多个相同任务的换皮移动App。
6. **为何没有并入其他App**：Mac采集器的权限、交互与生命周期不能直接作为iPhone/Watch App运行；移动端负责离开Mac后的阅读/轻量写入，Watch仅收摘要。一个移动工程覆盖宽窄布局，避免为同一任务另建相似App；开发者其他工具/个人业务App任务和数据边界不同，不放入此复盘客户端。
7. **共用代码与素材**：同族Mac共享自有品牌/图标/云端契约；AppConfiguration/AppLifecycle负责配置验证、备份、同步、生命周期与版本检查，RemoteUI/LaneSignal/PlatformCompat负责说明文字与平台诊断，这些基础模块也供同开发者其他Apple应用使用。业务模型、读写回执、待办分组、提醒事项映射、恢复和移动视图在本产品维护，没有其他App账号/数据。本工程MarkdownView是同源渲染责任源，hydro-deck复用其副本，旧options-desk已退役。
8. **第三方代码/SDK/内容**：使用Apple SwiftUI/UIKit、Foundation、EventKit、WatchConnectivity、WidgetKit、Keychain和iCloud；Package.swift无额外第三方客户端依赖，未集成广告/第三方分析SDK。公开脱敏源码MIT许可，版权曾田力/Tianli Zeng，入口https://github.com/zengtianli/notihub/tree/main/ios；本产品维护业务与平台适配。个人运行内容来自获授权服务，不进bundle/审核附件；公开截图和审核实例仅用合成数据，不复制个人库。
9. **谁提供及为何本人提交**：Notihub由曾田力/Tianli Zeng维护，是开发者自己的产品，不是代客户批量提交模板。ASC联系人沿受保护配置读取，具体密码只进ASC受保护字段，不写公开材料、环境或构建参数。
