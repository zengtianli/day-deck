# Notihub · 通知复盘使用教程

Notihub 是 iPhone / iPad 上的个人通知复盘入口，与 Notihub Mac 共用云端记录。早上查看待办，晚上回看通知与摘要，随时记下想法。它不会主动推送通知或显示角标。

## 首次连接

1. 打开「连接」，在「访问密码」中输入已有的云端访问密码。
2. 点「连接云端」。出现「云端已连接」后，切到「今天」或「通知」。
3. 在「连接」查看「最近同步」。这是数据同步时间；各页的「缓存更新」是当前设备取数时间，两者含义不同。

密码验证成功后保存于系统钥匙串。密码失效时回到「连接」重新输入；无需删除应用。自用版本的安装或更新由持有设备的本人完成，本文不提供公开安装包。

## 今天：处理待办

列表按「逾期 / 今天 / 没定时间 / 之后」分组。顶部搜索会匹配标题、备注与联系人。点开一条可查看时间、备注和「从哪句话抽出来的」原文，再决定如何处理。

- 「标为完成」「不做了」直接保存云端。以成功提示及刷新后的列表为准。
- 「存进提醒事项/日历」显示「已排队，等待 Mac 添加到提醒事项/日历」。这只代表服务器收单；Mac 尚未处理时，Apple 提醒事项里可能还没有新条目。
- 下拉刷新取最新列表；右上角时间表示最近一次取数时间。

## 通知：回看一天

页面包含摘要、当天抽出的事项、统计和时间线。左右箭头只在已有记录的日期间切换；日历按钮可选择具体一天。缺少摘要时，通知与随手记仍可阅读。

搜索匹配当前这一天的通知应用、联系人、正文和云端笔记；搜索期间会收起摘要及统计，清空关键词即可恢复。长正文点「展开正文」阅读，读完可「收起正文」。搜索不跨所有日期。

## 随手记：保存想法

输入内容后点「记下来」，看到「已保存到云端 · 日期」后，检查下方「已记下的」或「通知」时间线。成功后输入框清空；失败时草稿保留在当前设备。

草稿绑定开始输入时的日期，跨天继续编辑时以输入框上方日期为准。空白内容及超过 20,000 字的草稿不能提交。Mac 上新写的笔记需要同步后才会出现；手机在线提交的笔记直接写入云端。

## 出错时怎么恢复

| 提示或现象 | 下一步 |
|---|---|
| 「连不上 day 站」 | 检查网络后下拉刷新。有旧缓存时继续阅读，并留意缓存时间；首次打开且没有缓存时不会凭空出现数据。 |
| 「被访问闸拦住了」 | 到「连接」更新访问密码，再返回目标页刷新。 |
| HTTP 404 | 云端没有所选日期，换一个已有记录的日期，或稍后刷新。 |
| 其他 HTTP 错误 | 稍后重试。保存失败时保留草稿，不要为了重试卸载应用。 |
| 「拿到的数据对不上契约」 | 记下提示中的字段，更新应用后重试；旧可读缓存仍保留。 |
| 「登录成功，读取记录时遇到问题」 | 登录已完成，读取仍失败；稍后刷新，并按页面的具体网络或服务错误处理。 |
| 提醒事项一直「已排队」 | 确认 Notihub Mac 正在运行及其队列处理状态，不将排队提示当成已添加。 |

卸载应用可能丢失此设备尚未提交的草稿和离线缓存。反馈问题时提供版本、发生日期、操作步骤及脱敏错误文字；不要附密码、私人通知全文或包含真实联系人信息的截图。

开发者固定验收入口及覆盖范围见 `scripts/accept/`；公开演示录制边界见 [demo-recording.md](demo-recording.md)。
